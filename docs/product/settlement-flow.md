# 정산 플로우

## 원칙

정산은 모임 단위가 아니라 약속 단위로 생성한다. 정산 생성은 이미 시작한 약속에서만 가능하며, 시작 전 약속에는 CTA를 노출하지 않는다.

정산 상태는 세 단계만 사용한다.

| 상태 | 의미 | 사용자 노출 |
| --- | --- | --- |
| `draft` | 약속 참여자가 장소별 결제 항목을 함께 입력하는 상태 | 채팅 상단에 `정산 입력 중` 배너 |
| `finalized` | 송금 방향과 금액이 확정된 상태 | 채팅 상단에 정산 공지 |
| `completed` | 받을 사람이 모든 수취 완료를 확인한 상태 | 채팅 상단에서 숨김 |

한 약속에는 활성 `draft` 또는 `finalized` 정산을 하나만 둔다. 이미 활성 정산이 있으면 새로 만들지 않고 기존 정산으로 이동한다.

## 진입 흐름

```text
약속 상세
  -> 정산 만들기/보기
      -> 장소별 draft 편집
      -> 미리보기
      -> 정산 확정
      -> 정산 진행/완료 화면
          -> 정산 근거

모임 채팅
  -> 상단 정산 배너/공지
  -> + 버튼
      -> 진행중/지난 약속 선택
      -> 정산 만들기/보기
```

약속 상세의 정산 CTA는 `now >= startsAt`일 때만 보인다. `endsAt`이 없으면 `startsAt`을 기준으로 정산 가능 여부를 판단한다.

## Draft 편집

- draft는 약속 방문장소별 section과 장소 없는 비용을 위한 `기타 비용` section으로 구성한다.
- section마다 결제자를 선택한다.
- section 안에는 `메뉴별 추가`와 `균등분할 추가` 항목을 제한 없이 추가할 수 있다.
- 메뉴별 항목은 부담 대상자를 전체, 직접 선택, 금액 다르게 중 하나로 지정한다.
- 전체/직접 선택은 선택된 대상자에게 균등 배분한다.
- 금액 다르게는 대상자별 부담 금액을 직접 입력하며, 입력 합계가 항목 총액과 정확히 같아야 저장할 수 있다.
- 결제자와 대상자 식별자는 DB UUID `userId`를 사용한다. `publicId`/친구 코드는 정산 입력 식별자로 쓰지 않는다.
- 저장 요청은 서버에서 쓰기 lock으로 직렬화한다. 충돌이 감지되면 최신 draft를 다시 불러와 확인하도록 안내한다.

## 계산과 확정

정산 계산의 source of truth는 Spring API다. Flutter는 입력과 표시만 담당한다.

서버 계산 규칙:

1. 사용자별 `paidTotal`, `owedTotal`, `net = paidTotal - owedTotal`을 계산한다.
2. `금액 다르게` 항목은 대상자별 직접 입력 금액을 `owedTotal`에 반영한다.
3. 균등 배분 항목의 나머지 원 단위는 `publicId` 오름차순으로 1원씩 배분한다.
4. 부족한 사람에서 초과 지출한 사람으로 greedy matching하여 최소 이체 목록을 만든다.
5. preview는 DB write와 outbox write를 하지 않는다.
6. finalize는 정산 결과, 이체 목록, 채팅 활동, 알림 outbox를 저장한다.

## 완료 처리

- 송금자는 transfer 단위로 `송금 완료 알리기`를 누를 수 있다.
- 수취자는 transfer 단위로 `수취 완료하기`를 누른다.
- 수취자 전원이 받아야 할 transfer를 수취 완료하면 settlement는 `completed`가 된다.
- 완료 처리는 되돌릴 수 없다.

## 결과 화면

- 상단 participant grid는 한 줄 최대 4명까지 배치한다.
- 받을 사람은 왕관 아이콘을 표시한다.
- 완료된 사용자는 초록 체크 아이콘을 표시한다.
- 본인 역할에 따라 `송금 완료 알리기` 또는 `수취 완료하기` 버튼을 보여준다.
- `정산 근거` 버튼으로 계산 근거 화면에 이동한다.
